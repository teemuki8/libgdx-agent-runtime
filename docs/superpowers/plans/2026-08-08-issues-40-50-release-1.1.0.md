# Issues #40–#50 and Release 1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every open agent-runtime issue through one focused PR per issue, then create and stage release 1.1.0 without publishing it to Maven Central.

**Architecture:** Land shared diagnostic and lifecycle safety first, then capture bounds, registry correctness, retained-history protocol 1.14, and transport framing/serialization. Preserve every Java 1.x API and protocol 1.0–1.13 wire contract; expose new behavior only through additive Java members and protocol 1.14 where the wire shape changes.

**Tech Stack:** Java 25, Gradle 9.6.1, JUnit Jupiter 6, Jackson 2.22 protocol codec, MCP Java SDK 2.0/Jackson 3 adapter, Reactor, GitHub Actions, Xvfb, Sonatype Portal OSSRH Staging API.

## Global Constraints

- Preserve module direction: `runtime-mcp -> runtime-protocol -> runtime-core <- runtime-libgdx`.
- Keep `runtime-core` JDK-only; no Jackson, MCP, transport, filesystem, shell, networking, reflection, or hidden threads.
- Preserve binary/source compatibility for published Java 1.x APIs and exact protocol 1.0–1.13 command, response, error, bound, JSON, and MCP contracts.
- All new collections, strings, counters, queues, histories, diagnostics, requests, and responses are deterministically ordered and hard-bounded before expensive allocation or retention.
- Capture-thread code owns registration, lifecycle mutation, frame capture, events, decisions, causes, and callback execution; completed immutable snapshots remain queryable from any thread.
- Every issue uses a fresh branch from current `origin/main`, a failing behavioral test first, a ready issue-only PR with `Fixes #N`, exact-head review/CI, merge verification, and local-main reconciliation.
- Linux fixture and full gates run under `xvfb-run`, never the active desktop display.
- Release authority ends after GitHub release creation and validated Maven Central staging; never call the immutable Maven Central publish endpoint.
