# 2.1.0

Release 2.1.0 adds first-class deterministic fixed-step simulation evidence and a production-quality
Box2D integration. It is an additive minor release: existing Java integrations and exact protocol
1.0-1.13 and 2.0 clients remain supported, while new simulation capabilities use protocols
2.1-2.4.

The application remains authoritative for its main loop, input scheduling, mutation, rendering,
Box2D world and listener lifecycle, scenario reset, native-object replacement, and disposal. The
runtime creates no hidden thread, timer, renderer, physics loop, or object traversal.

## Published artifacts

All artifacts require Java 25 and use group `io.github.teemuki8`:

- `agent-runtime-core`
- `agent-runtime-libgdx`
- `agent-runtime-box2d` (new in 2.1.0)
- `agent-runtime-protocol`
- `agent-runtime-mcp`

`runtime-fixtures` and `runtime-examples` are repository qualification and consumer-guidance code;
they are not published.

## Highlights

### Authoritative simulation ticks

The JDK-only simulation timeline distinguishes simulation ticks from render activity and runtime
capture frames. Every attempted tick can retain:

- session-monotonic and epoch-relative tick identity;
- configured, supplied, and application-reported executed delta;
- accumulated epoch simulation time and pause/running source;
- resulting immutable runtime-frame correlation; and
- typed mismatch, callback, capture, eviction, or incomplete evidence.

Baseline frame 0 is not a simulation tick. Normal and controlled execution use the same timeline,
and a supplied fixed delta is never presented as executed unless application code acknowledges it.

### Canonical fixed-step integration

`runtime-core` owns an integer-nanosecond bounded accumulator, and `runtime-libgdx` provides the
small facade used from `ApplicationAdapter.render()`. The helper clamps render delta, caps retained
accumulation, limits catch-up ticks, records dropped time/ticks, preserves the partial remainder
across pause/resume, and supports exact configured-step advancement while paused. Interpolation
alpha is presentation-only.

The canonical shape is:

```java
simulation = LibGdxFixedStepSimulation.acknowledged(runtime, configuration, tick -> {
    world.step(tick.fixedStepSeconds(), velocityIterations, positionIterations);
    gameLogicAfterPhysics();
    return tick.fixedStepNanos();
});

// Application-owned render loop
simulation.update(Gdx.graphics.getDeltaTime());
renderGame(simulation.interpolationAlpha());
```

### Explicit Box2D adapter

The new `agent-runtime-box2d` artifact exposes only worlds, bodies, fixtures, shapes, and joints
explicitly registered by application code under stable semantic IDs. It never uses native pointers,
Java identity, reflection, `userData`, or arbitrary object traversal.

Capture copies mutable native values into closed bounded runtime entities. World testimony includes
solver settings and an explicit render-units-per-metre transform. Shape vertices, registrations,
properties, histories, and diagnostics are bounded before retention. Applications explicitly
rebind or unregister replaced native objects; the adapter never disposes them.

### Contact evidence

Applications install or compose the adapter listener and wrap each authoritative `World.step` they
want captured. Begin, end, pre-solve, and post-solve values are copied before the callback returns.
Stable canonical endpoints, sensor state, child indices, points, normals, old manifolds, and
normal/tangent impulses are present only where Box2D supplies them.

Bounded callback records and active-contact snapshots correlate to simulation ticks and completed
runtime frames. Truncation, unmapped endpoints, callback failures, reset, late callbacks, and
missing frame correlation make evidence incomplete; they are never interpreted as proof that no
contact occurred. No gameplay causality is inferred.

### Physics-oriented assertions

The JDK-only simulation assertion union evaluates immutable retained tick/frame evidence. It covers
exact properties, approximate scalars/vectors, area and magnitude checks, body distance, wrapped
angles, exact event selectors, bounded object-list subsets, conjunctions, final-state predicates,
and every-tick predicates. `Box2dAssertions` compiles body, fixture, world, and contact checks into
that generic model without retaining or querying native objects.

Results preserve PASS / FAIL / INCONCLUSIVE. Missing, failed, evicted, uncorrelated, truncated, or
adapter-incomplete evidence cannot produce a misleading negative or temporal PASS.

### Selected deterministic comparison

Simulation determinism reuses the existing bounded repeated-scenario engine. A specification names
the scenario, seed, fixed step, configuration facts, scheduled registered inputs, exact tick count,
and selected observable evidence. `Box2dDeterminism` adds data-only selection helpers for registered
physics entities and contact events.

Results identify the first differing simulation tick, both run/frame correlations, entity or event,
field/property, and values. Equality covers only the selected immutable evidence under the same
native library, platform, configuration, initial state, fixed-step sequence, and input script. It
is not a whole-program, rendering, replay, rollback, or cross-platform floating-point determinism
claim.

### Agent cookbook and native qualification

The non-published examples module compiles four consumer applications: basic inspection, a complete
controlled workflow, same-JVM stdio MCP hosting with a replayable closed transcript, and an
actual-native deterministic Box2D example. CI validates cookbook links, tool names, dependency
versions, transcript schemas, and the rule that public API or agent-visible contract changes update
the cookbook in the same pull request.

The Linux Xvfb conformance fixture uses real LWJGL3 and Box2D desktop natives for ball drop,
dynamic-body collision, and input-driven player movement. It proves scenario reset, checkpoint and
recording integration, exact ticks, contacts, assertions, deterministic reruns and divergence,
render independence, and deliberate timing, catch-up, scale, registration, and truncation failures.

## Protocol compatibility

Protocols 1.0-1.13 and 2.0 keep their exact supported command and response shapes. Release 2.1.0
adds:

- Protocol 2.1: `runtime_simulation` and `runtime_simulation_ticks`.
- Protocol 2.2: fixed-step state/history and `runtime_simulation_advance`.
- Protocol 2.3: `runtime_simulation_assert`.
- Protocol 2.4: `runtime_simulation_determinism_check`.

`ProtocolVersion.CURRENT` is 2.4. Unsupported exact versions and commands fail before execution.
Box2D inspection and contacts reuse ordinary entity, history, event, assertion, and determinism
schemas; Box2D types do not enter `runtime-core`, protocol commands, or MCP transport values.

## Upgrade and adoption

Existing 2.0.0 consumers can update their current runtime modules to 2.1.0 without adopting the new
simulation APIs. Consumers adopting deterministic physics should:

1. Align every runtime artifact on version 2.1.0.
2. Add `agent-runtime-box2d` only when Box2D evidence or factories are needed.
3. Register the fixed step before `runtime.start()` and return the delta actually executed.
4. Register only selected Box2D objects under stable IDs and configure the explicit unit transform.
5. Install `contacts.listener()` or `contacts.compose(applicationListener)` and wrap the
   application-owned `World.step` with `contacts.captureStep(...)`.
6. Use protocol 2.1-2.4 only for the corresponding additive commands.
7. Treat truncation, eviction, failed ticks, and `complete=false` as incomplete evidence.

See the [agent cookbook](../guides/agent-cookbook.md),
[getting-started guide](../guides/getting-started.md), and
[bootstrap migration guide](../guides/bootstrap-box2d-migration.md) for executable integration
recipes.

## Qualified platforms and dependencies

The release is compiled and tested with JDK 25 on Linux, Windows, and macOS. Actual-native LWJGL3
and Box2D conformance is qualified on Linux under Xvfb. Android, iOS, web, and cross-platform Box2D
bitwise equality are not release claims.

The reviewed direct dependencies are libGDX 1.14.2, Jackson 2.22.1, Java MCP SDK 2.0.0, and JUnit
6.1.2. `runtime-core` remains JDK-only and resolves only `java.base` under `jdeps`.

## Staging boundary

The reviewed tag and GitHub release are separate from signing, Central staging, inspection, and
immutable publication. Publishing the GitHub release may start the protected `Stage Maven Central`
workflow, but the environment approval remains a distinct maintainer action.
Maven Central publication requires separate authorization. Publishing also requires current terms
acceptance, a validated candidate, and inspection of the exact five coordinates. This release note
does not claim that version 2.1.0 has been staged or published to Maven Central.
