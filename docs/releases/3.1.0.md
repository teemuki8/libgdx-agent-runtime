# libGDX Agent Runtime 3.1.0

This additive release introduces SimulationFrameOwnership and an explicit CALLBACK registration
mode for application callbacks that already own their runtime frame, including gameplay bridges.
The existing simulation registration overload retains RUNTIME ownership.

A controlled callback must complete exactly one frame with the supplied fixed-step delta.
Missing, multiple, unclosed or wrong-delta frames fail closed. Caught nested-frame failures remain
observable. Input preparation occurs before callback execution. Capture remains application-thread
owned, bounded and fail-stop: the runtime does not roll back application state or silently retry
a failed tick. Some provider failures require rebuilding the application-owned runtime.

Protocol and MCP request shapes are unchanged. See ADR 0021, the agent cookbook, and
qualification/gameplay for the real gameplay consumer. Applications must opt in explicitly;
upgrading dependencies alone does not change their tick ownership.

Align agent-runtime-core, agent-runtime-libgdx, agent-runtime-box2d, agent-runtime-protocol and
agent-runtime-mcp on 3.1.0 when available. Examples, fixtures and qualification consumers are
not published. JDK 25 and the official Box2D 3 backend remain the baseline.

Staging, validation and immutable publication are separate operations. This candidate note is
not evidence that Central has published the artifacts.
